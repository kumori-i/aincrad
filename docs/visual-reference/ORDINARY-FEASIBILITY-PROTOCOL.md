## Question and fixed trajectory

Can the sole default world produce opportunities, paid observed demonstrations,
private exemplar additions and later association-matched choices while ordinary
survival remains active? World seed 74193, communication seed 211, normal speed 1x,
existing 1/60 simulation loop, default positions, ecology, bodies and decisions.
No forced meetings, resource changes, manual stepping, scheduling holds, learner
probes, alternate worlds, imported weights or target injections. The observer
starts the ordinary application once. It never resumes a paused run.

Target: first passive observation of elapsed >= 1200 simulation seconds. Poll
approximately every wall second; project detailed metrics at least 10 simulation
seconds apart, plus initial and terminal records. Pause through the ordinary API
at the first observed target. Record threshold and paused elapsed and wall times.
Overshoot >2 simulation seconds is a retained deviation, not a rerun reason.

The first bound is immutable: 30 minutes from native launch including boot;
32 MiB total structured evidence; 16 MiB total native stdout/stderr and images.
Reserve 256 KiB of structured capacity for failure/terminal evidence. Count actual
UTF-8 bytes including JSONL separators. Whole records rejected by a cap are not
partially written. At a cap, communication fault, rollback, unexpected pause or
invariant failure: request ordinary pause once, allow 5 seconds for evidence and
close, then terminate if necessary. Pause unconfirmed means incomplete. Never
rerun or retune. Record additional causes without replacing the first one.

pending counts, correction attempts, new examples, support-only updates, conflicts,
abstentions, anchors and partner/example occupancy. Track terminal observed
correctness separately for association-match and uniform-exploration choices.

creative concept formation, or generalized language.

The observer reads the real attachment and body snapshots. It transports compact
projections, never private vectors or pixel ledgers. It records bodies, positions,
identity serials, lifecycle, own survival history counts and ordinary clocks.
The source ledger retains 256 events; missing ID ranges and evicted pending
outcomes are explicit, never reconstructed. Passive reads have overhead; report
poll/read counts and durations. Initial/terminal reads are outside summary cadence.
No shuffled/erased controls in this first feasibility run.

Only bounded JSONL evidence and bounded stdout/stderr logs are archived. No raw
save, Chromium profile, application copy or image archive is retained. Temporary
profile/build/cache files are working runtime data, not evidence; they are deleted
only after child closure. This preserves a small evidence budget without claiming
full-save replay. A failure retains its bounded observations and failure record.

## Source and one-time activation

The frozen protocol module identifies B commit/tree/runtime fingerprint. The
source manifest pins all B runtime and desktop files, package lock and harness
dependencies, plus each prospective C source file. The manifest cannot hash
itself: its SHA256 and the complete C commit/tree must be recorded externally.
The owner/root must approve that exact complete commit and manifest before creating
`experiments/reference-acquisition-v1-once` at that immutable SHA. The reserved ref
must never be updated, deleted/recreated, reused or used for a rerun. No default
branch fetch or mutable latest lookup occurs at execution.

Workflow activation uses only `create`, the exact branch/type, and attempt 1.
The runner additionally verifies clean HEAD equals GITHUB_SHA, exact event/ref,
workflow name, Linux x64, unprivileged execution, actual sandbox preferences,
strict test route, fresh profile/current save absent, initial elapsed 0, normal1x,
fixed seeds and built/runtime fingerprint. These guards are not themselves owner
approval; external source approval and the sole authorized ref creation are needed.
Failure to trigger is a no-run blocker, not permission to fall back to push/dispatch.

GitHub documents discovery at the event's associated commit/ref, and the create
SHA as the last commit on the newly created branch/tag; create has no default-
branch-only restriction listed. This is documented trigger viability, not a tested
activation: [workflow discovery](https://docs.github.com/en/actions/concepts/workflows-and-actions/workflows)
and [create semantics](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#create).
