# Witnessed carcass processing (H1)

This bounded capability repairs finite carcass handling and preserves a
witnessed terminal-strike identity. It is not hunting completion, a new food
recipe, animal anatomy, sustainable feeding, or a pursuit-policy change.

## Physical operation

Carcass pulling preflights finite usable stock, the destination, a strictly
allocatable next object ID and the global material slot. It does not call the
side-effectful overflow path to discover that the slot is full. A refused pull
leaves the entire physical ecology unchanged. Timed completion separately checks
four-item hand capacity and the existing owner, scene, reach and line-of-sight
guards; already-paid handling and body costs remain paid.

Successful pulls detach at most 100 g of the already-existing source. The piece
inherits spoilage and age; source remainder is computed by subtraction before
commit. Existing sub-gram residue/detrital overflow handling remains in place.
Current carcass yield is still derived from animal energy, not conserved live
anatomy. No whole-animal mass/water conservation or complete watershed accounting
is claimed. A full global material array refuses even a last-piece pull that
would eventually remove its source. Dropping a held item frees a hand, not a
material slot.

Runtime action identity belongs to its original actor. Copied/reloaded commands
cannot execute, and completion/cancellation settles the original so that a
reattached cancelled action or throwing callback cannot replay a transfer or
successor observation.

## Witnessed identity, not ownership or food knowledge

Only an actual successful terminal strike that created a carcass returns its
`resultObjectId`. The action target stays the old animal ID. The actor receives
that actual object's ordinary public sensory description, not hidden species,
calories, reserves or yield; the carcass is not added to inventory. Capped death
still occurs and follows existing overflow accounting, but returns no phantom
successor. Natural/predator deaths do not manufacture an actor's causal receipt.

The optional relation is retained only in the existing matching action receipt
and discovery experiment. Shared proof checks require exact original action ID,
target, timestamp, successful terminal-strike outcome, matching canonical positive
successor IDs distinct from the target, and no material/ingestion acquisition
fields. Raw presence is validated before bounded compaction can discard an
invalid field. Null, empty, zero, malformed, one-sided, self-linked, mismatched or
orphan identities fail closed. Both fields absent preserves old history. The
carcass need not still exist for the historical relation to remain valid.
Ordinary bounded retirement may remove the pair without preserving a hunt forever.

Nothing learns a strike recipe. Only the pre-existing actual exact-carcass
pull → sample → delayed effect can establish a technique for that exact source.
Another animal or carcass is not generalized from it. A whole carcass remains too
heavy to grasp and cannot be sampled directly.

It launches directly and uses `aincrad.world.v2`; retired save formats are not migrated. Current corrupt bytes remain protected. Short autonomous adoption is diagnostic, not a capability-release gate. Physics, exact proof, conservation within the stated model, current saves and sandboxed native persistence remain required.

## Historical H1 preservation boundary

At the original H1 checkpoint, the Ozark save remained v9 with exactly `{plantLifecycle: 1}`, its existing storage
key, physical stocks, next-ID history and elapsed time. Unmodified-main v9 fixtures
covered fresh/progressed worlds, old strike receipts, held flesh, pending digestion
and retained effects. Loading adds no objects or relation backfill. Optional new
history can cause an older binary to protect/reject an occupied save; reverse
binary readability is not promised, and original bytes must not be reset.

Structural tests use disclosed static or low-health fixtures, not hunting
measurements. Separate native-loop measurements use one predeclared seed-74193

search. That is not evidence of autonomous travel from spawn. Commands are
external test inputs, not a supplied or learned hunt recipe. Outcome details and
exact trace fingerprints accompany the frozen implementation evidence.

## Validation commands and remaining release gate

- `node --test tests/carcass-processing*.test.mjs`
- `npm run check`
- `npm run build`
- `npm run smoke` in a supported sandboxed desktop environment.
- `node scripts/verify-carcass-desktop.mjs --output test-results/carcass-native`
  for actual isolated Electron close/reopen at relation, successful pull and
  active-processing checkpoints; `--prepare-only` does not execute Electron.
- `scripts/measure-carcass-encounters.mjs` records the single declared frozen
  measurement pair. It is not a recurring success gate or a tuning loop. Consult
  its argument validation and saved protocol/evidence before any separate study.

The native workflow uses short OS-temp profiles and real close/closed/will-quit
assertions, verifies sandbox preferences, does not read retired slots, checks
finite physical and actor evidence after reopening, and proves paused/closed time
adds nothing. It never uses a real profile or bypasses the sandbox. Preparing a
harness or a Node JSON roundtrip is not native disk validation. When desktop
execution is blocked, release stays pending supported CI, not silently passed.

The original H1 checkpoint did not include fishing. The current integration adds the separately reviewed finite-fishing capability without changing H1 prey selection, flee speed, ordinary damage, reach or food-proof definitions. Historical encounter outcomes above remain historical measurements, not claims about the revised landscape.
