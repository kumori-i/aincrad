# Renewable ecology and food sharing native QA

Run `node scripts/verify-renewable-sharing-desktop.mjs` from an installed checkout on a supported desktop. Linux requires an unprivileged account, a display and window manager; CI uses Xvfb plus Openbox. Windows uses its native desktop. Chromium sandbox bypass flags are prohibited.

`node scripts/verify-renewable-sharing-desktop.mjs --prepare-only` builds the application and writes the generated runner without executing Electron. Preparation is not a native test pass. Artifacts default to `test-results/renewable-sharing-desktop/run-*`; `AINCRAD_RENEWABLE_QA_OUTPUT` may select another artifact root. Profiles remain disposable directories under the operating system's temporary root, independent of the real user profile.

## Physical fixture

The only encounter shortcut places both actors on a valid dry-ground point beside a real source. It does not change body stores, ecological coefficients, food, clocks or evidence. The fixture advances environment, ecology and both bodies together through ordinary fixed steps, performs paid fruit acquisition and sampling, waits for the donor's actual delayed exact-object effect, offers the remaining held object and starts a voluntary recipient grasp.

The recipient must pay time and metabolism. Offer, consent and the first half-second cannot transfer ownership. On completion the same finite object changes hands exactly once, without granting an independent meal, bodily effect or technique. The recipient then offers the same item back, without acceptance. This counter-offer cannot change ownership and supplies a negative restart control.

During the same real shared-clock ticks, aquatic primary production and feeding must increase their ledgers. The aquatic mass, energy and water audit must remain balanced. This short native fixture does not exercise multi-day growth or reproduction; those mechanics have separate deterministic long-run tests. Explicit offers here do not establish autonomous requesting, sharing policy, navigation or survival.

## Required native evidence

Two independent Electron processes write and reopen the sole current `aincrad.world.v2` save. The harness checks:

- Actual sandbox, context isolation, disabled Node integration and web security.
- The native renderer fingerprint matches the application built from the checkout.
- Normal native window `close`, `closed` and application `will-quit` events.
- Exact disk bytes across closed processes, with no closed-time progression.
- Restored renewable stocks, population, ledgers, recipient inventory and distinct personal evidence, not a fresh default world.
- Pending offers do not restore consent authority; the unaccepted object remains donor-owned.
- Escape pause and view-only camera previews do not advance or mutate the world.
- Actual native screenshots of the restored held material, saved attributed food offer conversation and watershed view.

Process logs, failure screenshots and regular profile files are retained. Profile archival excludes symlinks and special files and runs only after child processes close. Reports distinguish preparation from actual native execution. The new workflow runs independently on Windows and Linux; both native jobs must pass before claiming platform coverage.
