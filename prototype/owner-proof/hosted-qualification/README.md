# Independent hosted display qualification

This directory is an unexecuted, setup-only candidate. Its intended repository destination is `prototype/owner-proof/hosted-qualification/`. It is prepared outside the owner-proof checkout so that it cannot alter that proof's existing freeze inventory. It contains no world fixtures, Stage A ZIP/importer, application startup, owner simulation, Cardinal work, save experiment or timing tape.

## Approval and trigger

`workflow.proposed.yml` is a proposal, not an installed workflow. Its eventual destination is `.github/workflows/owner-hosted-qualification.yml`. The proposed publication sequence is: first create `proof/owner-hosted-qualification` at reviewed baseline `1f20f401f720b61069dcea06d10cc4e885e0b1f6`, where this workflow is absent; then install and push the exact approved setup commit once. Publishing that second push starts qualification immediately. Each push also triggers the existing `Verify world` check/build workflow. That existing workflow has no dependency installation or artifact upload. The desktop packaging/smoke workflow is main-push/manual only and does not run for this branch. Opening a PR adds another check/build run and is unnecessary; the proposal is branch push only.

The job and launcher require repository `kumori-i/aincrad`, that exact feature branch, run attempt 1, the fixed baseline `before`, the exact triggering commit as `after`, and a normal non-created, non-deleted, non-forced public-repository push event. Preflight reads at most 1 MiB of the event file, parses it with JSON.parse and retains only these approved fields. It never logs the full event or commit descriptions. A subsequent ordinary push has a different `before` and skips/rejects. This is a transition gate, not a global lock across rewritten history; force-reset, branch recreation or other retry sequences are not authorized. No other push branch, PR or manual dispatch is configured. No publication or execution is authorized merely by this source preparation.

Review the complete source-manifest SHA and proposed workflow SHA before approving publication. The workflow embeds the reviewed source-manifest hash, checks out its exact triggering commit with the pinned official checkout action and `persist-credentials: false`, and grants only `contents: read`. The manifest covers the listed code, tests and this README, plus exact baseline package metadata hashes. It excludes itself and the proposed workflow to avoid circular hashes. The launcher verifies the installed workflow equals the reviewed proposal byte-for-byte and records its SHA and the triggering commit/run identity. No repository write token, artifact upload, PAT, OIDC or secrets are requested. [Checkout v4.2.2](https://github.com/actions/checkout/releases/tag/v4.2.2).

## Admission evidence

- The supervisor creates one owned Xvfb process with exact 1440×900×24 geometry, 96 DPI, a fresh private MIT-MAGIC-COOKIE-1 authority and `-nolisten tcp`. It verifies authenticated access, an explicit cookie-free authorization denial, a successful authenticated recheck and no listening IPv4/IPv6 entry at the X display TCP port. The cookie goes to xauth through stdin only and is removed at cleanup.
- Electron uses the exact lockfile runtime, frozen copies of only the six qualification runtime files, a new private profile, an allowlisted custom protocol and fixed security preferences. Node integration is disabled; sandbox and context isolation stay enabled. No sandbox-disabling flags or forced device scaling are permitted. The existing `--disable-gpu` software-rendering choice is explicit; it does not disable the renderer sandbox.
- The real page draws a fixed geometric pattern into a 1440×900 canvas. Native content size, page inner dimensions, canvas logical/CSS size, DPR, capture raster and five known pixel samples must agree. The retained PNG is the actual 1440×900 native capture, never a scaled replacement.
- A preload-origin report must show sandboxed renderer and isolated context. Main obtains the renderer's OS PID, checks process identity, real executable, argv, Seccomp mode 2, NoNewPrivs 1, zero permitted/effective/ambient capabilities, and user/PID/network namespaces distinct from the Electron main process. The bounded, strictly parsed renderer NSpid chain must begin with the observed host PID/status.Pid and end with the sandboxed preload's process.pid (getpid in its innermost PID namespace). The evidence must agree; configuration flags or absence of Node alone do not qualify. Unreadable or inconclusive `/proc` evidence stops unavailable, with no privileged retry. These observations establish the declared mechanisms, not proof against every sandbox escape. [Electron process fields](https://www.electronjs.org/docs/latest/api/process), [Electron 44.7.0 preload PID binding](https://raw.githubusercontent.com/electron/electron/v44.7.0/shell/renderer/electron_sandboxed_renderer_client.cc), [Chromium POSIX getpid implementation](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/base/process/process_handle_posix.cc), [Chromium Linux sandbox](https://chromium.googlesource.com/chromium/src/+/main/sandbox/linux/README.md), [kernel proc evidence](https://docs.kernel.org/filesystems/proc.html).
- The page checks absent Node globals and makes four local negative probes: eval, inline script, fetch and worker. The latter targets are deliberately served by the fixed protocol so transport failure cannot substitute for CSP enforcement. Every denied probe requires the exact enforced CSP policy, effective directive and blocked URI in `securitypolicyviolation` evidence. No external network target is used. The page exposes only one fixed, once-only report IPC; navigation, downloads, permission requests and new windows are denied.

This viewport qualification establishes no world pixel equivalence, hide/show timing, six-arm outcome, physical monitor/compositor, Retina/GPU or 32-GB-laptop performance result. It also cannot qualify the existing proof's distinct Xorg backend without separate review.

## Bounds and failure behavior

The qualification deadline is 45 seconds, including before/after source and runtime verification. All inventory traversals and reads share one cancellation/deadline budget with at most 4,096 charged entries, 2 GiB of aggregate bytes and depth 12; each inventory has at most 512 files and each binary at most 512 MiB. Directory enumeration is incremental and bounded. Post-cleanup verification uses the same original budget. Aborted/deadline reads destroy their stream and cannot qualify. Owned-group and cookie cleanup has a separate maximum five-second tail, with group closes in parallel. Electron has a 20-second outer process limit and a 15-second native startup limit; Xvfb has a 35-second process lifetime. Display readiness has at most ten bounded probes against the same server, without changing configuration or restarting qualification. Each owned group gets bounded TERM/KILL cleanup and positive absence checks. A child exit alone does not prove its descendants exited. Signals and output limits terminate owned work. A process is no longer live at exit, while its result remains pending until stream close; late output is counted against the same limit. Missing stream close fails after 500 ms. Terminal callbacks cannot recreate timers. Cleanup targets only newly spawned groups and newly created authority files; no system locks, directories or unrelated processes are removed.

All qualification failures have status `unavailable` and a nonzero exit. Source/runtime changes or incomplete cleanup invalidate an apparent native pass. There is no fallback, success-seeking native retry or scientific threshold modification. Local private report/profile files may remain in the ephemeral job directory; cookie files must be removed. Production state is never opened.

## Public log boundary

Publication approval must cover public source and these outputs: allowlisted GitHub run/commit/image metadata, CPU/memory/kernel details, fixed source and binary hashes, selected kernel settings, process IDs and namespace/capability/sandbox diagnostics, viewport/CSP observations and the fixed-pattern screenshot. It does not expose application profiles, world history, credentials, cookies, arbitrary environment variables, or raw install/native stderr.

Source and output reads use bounded same-file-descriptor reads and reject growth or identity/size changes. The structured qualification report is capped at 128 KiB. The actual PNG must fit within 64 KiB; its base64 is emitted in numbered chunks of at most 6,144 characters, with byte count and SHA-256. An oversized screenshot fails instead of being resized. Installation failure logs remain local; public output includes only their size and hash. No Actions artifact or cache storage is created. The parent can retrieve job logs using the read-only connector and verify/reassemble the screenshot. Successful qualification output is evidence only; later proof implementation, transport, pixel tests and timing require independent review and explicit authorization.

## Deterministic local tests

Run `node --test qualification.test.mjs` from this prepared directory, or the same test at its final repository path. Tests use built-in Node APIs, pure policy fixtures, temporary files, mocked child processes and mocked signals/timers. Regressions cover the publication transition, hosted provenance, host/inner PID correlation, late-output drain, immediate exit liveness, inventory byte/entry/depth limits, aborted reads, retained post-verification deadlines and source growth. They never launch Electron, Xvfb, xauth, xdpyinfo, the application, a shell command, or a GitHub workflow. Importing `qualify.mjs` and `supervisor.mjs` is inert.
